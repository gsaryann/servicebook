# ServiceBook (Электронная сервисная книжка)

Полноценное мобильное приложение на **Kotlin + Jetpack Compose**, разработанное по макетам из Figma / PDF.

## 📱 Стек технологий
- **Язык:** Kotlin 2.2+
- **UI Toolkit:** Jetpack Compose (Material 3)
- **Архитектура:** Single Activity, NavHost (Navigation Compose), StateFlow Repository
- **SDK:** Android 36 (minSdk 26)

## 🗺️ Реализованные экраны и сценарии (согласно 32 экранам Figma)
1. **Онбординг (Стр. 1–2):** 2 интерактивных слайда с индикатором и кнопками «Продолжить» / «Начать» / «Пропустить».
2. **Авторизация (Стр. 3–10):**
   - Экран входа (`LoginScreen`)
   - Экран регистрации с обязательными полями и чекбоксом согласия (`RegisterScreen`)
   - Подтверждение входа через Telegram: одноразовый запрос на FastAPI-сервере, собственный контакт при регистрации и кнопки подтверждения/отклонения при последующих входах
   - Демо-авторизация Яндекс ID (`YandexAuthScreen`)
   - Проверка данных профиля (`CheckDataScreen`)
3. **Автомобиль & Главная (Стр. 11–14):**
   - Добавление авто (`AddCarScreen`): марка, модель, год, двигатель, пробег
   - Главный дашборд (`DashboardScreen`): виджет пробега, баннер ближайшего ТО, блок последней работы
   - Нижняя шторка (`ModalBottomSheet`) быстрого обновления пробега с валидацией
4. **Мастер добавления записи ТО (Стр. 15–19):**
   - Шаг 1: Выбор шаблона работы (Замена масла, Тормозные колодки, Шины, Другое)
   - Шаг 2: Ввод даты, пробега, стоимости и заметки
   - Шаг 3: Превью чека с модальной шторкой выбора «Камера / Галерея»
   - Экран успеха (`RecordSuccessScreen`)
5. **История обслуживания (Стр. 20–24):**
   - Фильтрация по чипам: Все, Масло, Тормоза, Шины
   - Суммарный подсчёт годовых расходов (динамический)
   - Карточка записи с деталями и чеком
   - Диалог подтверждения безвозвратного удаления с сохранением чека
   - Empty state (экран первого запуска)
6. **Напоминания & График ТО (Стр. 25–27):**
   - Цветовая индикация регламентов (просрочено / подходит срок / в норме)
   - Настройка сроков и пробега ТО
   - Переключатель push-уведомлений
7. **Документы (Стр. 29–32):**
   - Хранилище чеков и заказ-нарядов с фильтрами
   - Добавление документа через камеру/галерею
   - Просмотр чека с реквизитами автосервиса и кнопкой «Поделиться файлом»
8. **Профиль (Стр. 28):**
   - Личные данные, быстрый переход к авто/напоминаниям, выход из аккаунта

## 🚀 Запуск проекта
1. Откройте **Android Studio**.
2. Выберите **File → Open** и укажите папку `D:\AndroidStudioProjects\ServiceBook`.
3. Дождитесь автоматической Gradle-синхронизации (все зависимости уже скачаны).
4. Выберите эмулятор или подключённый Android-смартфон и нажмите **Run** (зелёный треугольник).
5. Готовый собранный APK находится по адресу:
   `D:\AndroidStudioProjects\ServiceBook\app\build\outputs\apk\debug\app-debug.apk`


## Локальная демонстрация Telegram-авторизации

Сервер и Telegram-бот запускаются на твоём ПК, без платного хостинга. Подробная инструкция находится в [server/README.md](server/README.md).

Кратко:
1. Создай `server/.env` и задай случайный `INTERNAL_BOT_SECRET`.
2. Создай `bot/.env`, укажи `BOT_TOKEN` и тот же `INTERNAL_BOT_SECRET`.
3. Запусти `server/run_server.bat` и `bot/run.bat` в двух отдельных окнах.
4. Эмулятор использует `http://10.0.2.2:8000`. Для физического телефона добавь `servicebook.authApiUrl=http://IP_ТВОЕГО_ПК:8000` в корневой `local.properties`, затем пересобери APK.
5. Телефон и ПК должны быть в одной частной Wi-Fi сети; разреши порт 8000 в брандмауэре Windows только для частной сети.

Реальные секреты и локальная база SQLite в Git не добавляются.


## Проверки CI

Ветка `security-fix` запускает автоматические тесты Python-сервера и Telegram-бота, а также unit-тесты и debug-сборку Android-приложения.

CI также проверяет Python-тесты и debug-сборку Android-приложения в GitHub Actions.

Gradle wrapper permissions are normalized by CI before the Android build.
