# Локальный сервер авторизации ServiceBook

Сервер и Telegram-бот запускаются на одном ПК. Платный хостинг и публичный IP для демонстрации не нужны. Телефон должен быть подключён к той же частной Wi-Fi сети, что и ПК.

## 1. Подготовка сервера

1. Установите Python 3.11 или новее.
2. Откройте каталог `server`.
3. Скопируйте `.env.example` в `.env`.
4. Сгенерируйте общий секрет командой:

   ```powershell
   py -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

5. Вставьте полученную строку в `INTERNAL_BOT_SECRET` файла `server/.env`.
6. Сохраните файл. Не добавляйте `.env` в GitHub и не отправляйте секрет в переписку.

## 2. Запуск API

Из корня репозитория запустите `server/run_server.bat`. При первом запуске он создаст виртуальное окружение, установит зависимости и предложит создать `server/.env`. После настройки секрета запустите файл ещё раз.

Проверка на ПК: http://127.0.0.1:8000/health  
Документация API: http://127.0.0.1:8000/docs

Сервер слушает порт 8000 на сетевых интерфейсах ПК, чтобы телефон мог подключиться по локальному адресу.

## 3. Настройка Telegram-бота

1. Скопируйте `bot/.env.example` в `bot/.env`.
2. Укажите токен бота из @BotFather в `BOT_TOKEN`.
3. Оставьте `AUTH_API_URL=http://127.0.0.1:8000`.
4. Вставьте в `INTERNAL_BOT_SECRET` ровно тот же секрет, что и в `server/.env`.
5. Запустите `bot/run.bat` в отдельном окне. При первом запуске он создаст виртуальное окружение и установит зависимости.

Бот использует long polling: Telegram сам доставляет ему обновления, поэтому входящий публичный адрес и webhook не требуются.

## 4. Подключение Android

### Эмулятор Android Studio

Ничего менять не нужно: используется адрес по умолчанию `http://10.0.2.2:8000`.

### Физический телефон

1. Убедитесь, что ПК и телефон подключены к одной частной Wi-Fi сети (не к гостевой сети с изоляцией клиентов).
2. На ПК выполните `ipconfig` и найдите IPv4 активного Wi-Fi адаптера, например `192.168.1.15`.
3. В Android Studio откройте корневой файл `local.properties`. Не удаляйте существующую строку `sdk.dir`; добавьте отдельной строкой:

   ```properties
   servicebook.authApiUrl=http://192.168.1.15:8000
   ```

   Замените IP на адрес своего ПК. `local.properties` не попадает в Git.
4. Разрешите входящие подключения к TCP-порту 8000 в брандмауэре Windows только для частных сетей.
5. Пересоберите и установите debug APK на телефон.

## 5. Демонстрация

1. Запустите сервер и Telegram-бот на ПК в двух отдельных окнах.
2. Откройте ServiceBook на телефоне.
3. При регистрации заполните профиль и нажмите «Продолжить в Telegram».
4. В боте нажмите кнопку отправки собственного контакта. Пересланный контакт другого человека не принимается.
5. Приложение автоматически увидит подтверждение и завершит регистрацию.
6. Выйдите из аккаунта, снова введите номер и запросите вход. Бот покажет кнопки «Подтвердить вход» и «Отклонить».
7. После подтверждения приложение автоматически продолжит вход.

Запрос действует 5 минут. Повторное подтверждение уже обработанного запроса невозможно.

## 6. Тесты

Из корня репозитория:

```powershell
cd server
py -m pip install -r requirements-dev.txt
py -m unittest discover -s tests -v
cd ..\bot
py -m pip install -r requirements.txt
py -m unittest discover -s tests -v
```

Android unit tests: `gradlew.bat :app:testDebugUnitTest`. Сборка APK: `gradlew.bat :app:assembleDebug`.

## Ограничения демонстрационной версии

- SQLite хранится локально в каталоге `server`; сделайте резервную копию перед очисткой.
- Авторизация подтверждает Telegram ID на сервере, но профиль, автомобиль, история обслуживания и документы остаются в локальном хранилище Android. Синхронизации между устройствами нет.
- HTTP разрешён только в debug-сборке и только для доверенной локальной Wi-Fi сети. Не публикуйте порт 8000 в интернет.
- Для реального выпуска нужны HTTPS, ограничение сетевого доступа, защита от перебора, полноценные серверные сессии и безопасное хранение токенов.
